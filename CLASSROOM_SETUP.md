# BottleCRM - Classroom Setup

This repository is a classroom version of BottleCRM used for a software-system comprehension exercise.

The steps below create the same small BottleCRM environment and dataset for everyone in the class. You do not need to understand the BottleCRM code to complete this setup.

---

## 1. What you need

Before class, install:

- Git
- Docker Desktop
- a web browser
- a code editor such as VS Code

Make sure **Docker Desktop is running** before continuing.

### Windows

Install Docker Desktop.

Docker Desktop may ask you to install or update WSL 2. Follow the instructions shown by Docker Desktop and restart your computer if requested.

### macOS

Install Docker Desktop and start it.

On Apple silicon Macs, macOS may ask you to install Rosetta when Docker starts some containers. Install it if prompted.

---

## 2. Get the repository

Open a terminal and run:

```bash
git clone <CLASSROOM-REPOSITORY-URL>
cd django-crm-comprehension
```

If you have already cloned the repository, do not clone it again.

---

## 3. Check Docker

Run:

```bash
docker info
```

You should see information about both the Docker `Client` and `Server`.

Then run:

```bash
docker compose version
```

If either command fails, make sure Docker Desktop is running before continuing.

---

## 4. Start BottleCRM

From inside the repository directory, run:

```bash
docker compose up --build -d
```

The first run may take several minutes because Docker needs to download and build the required images.

When the command finishes, run:

```bash
docker compose ps
```

You should see the BottleCRM services running, including services such as:

- backend
- frontend
- db
- redis
- celery-worker
- celery-beat

If some services are still starting, wait briefly and run:

```bash
docker compose ps
```

again.

---

## 5. Prepare the database

Run:

```bash
docker compose exec backend python manage.py migrate
```

Wait until this command finishes.

You may see:

```text
No migrations to apply.
```

That is fine.

---

## 6. Create the classroom dataset

Run:

```bash
docker compose exec backend python manage.py seed_comprehension_data
```

This creates the small, fixed dataset used for the classroom exercise.

Do **not** run the normal `seed_data` command. The classroom exercise uses a deliberately smaller dataset.

---

## 7. Open BottleCRM

Open the following address in your browser:

```text
http://localhost:5181
```

You should see the BottleCRM interface.

> **Important:** Do not use `http://0.0.0.0:5181`, and do not use port `8000` for the main interface. Port `8000` is used by the BottleCRM backend.

---

## 8. Log in

The classroom account is:

```text
student@example.com
```

BottleCRM normally uses email-based login. Since this application is running locally, the classroom repository provides a development-login command.

Run:

```bash
docker compose exec backend python manage.py devlogin student@example.com --org MicroPyramid
```

You should see output containing:

```text
=== Paste into browser devtools ===
```

Below it will be a small piece of JavaScript.

### Copy the JavaScript

Copy everything beginning with:

```javascript
const y = ...
```

and ending with:

```javascript
location.reload();
```

### Open the browser console

With BottleCRM open at:

```text
http://localhost:5181
```

open the browser Developer Tools.

1. Right-click the page and choose **Inspect**.
2. Select **Console**.
3. Paste the JavaScript generated by `devlogin`.
4. Press Enter.

The page should reload. You should now be logged in to BottleCRM.

### If the browser prevents you from pasting

Some browsers display a security warning when you first paste into the Developer Tools console. Follow the browser's instruction to enable pasting, then paste the generated JavaScript again.

Do not manually modify the generated JavaScript.

## Starting BottleCRM later

You do not need to rebuild and seed the application every time.

After restarting your computer, open Docker Desktop and run:

```bash
docker compose up -d
```

Then open:

```text
http://localhost:5181
```

If you need to log in again, run:

```bash
docker compose exec backend python manage.py devlogin student@example.com --org MicroPyramid
```

and repeat the browser-console login step.

---

## Stopping BottleCRM

Run:

```bash
docker compose down
```

This stops the containers but keeps your database.

The next time you run:

```bash
docker compose up -d
```

your existing classroom data should still be available.

---

## Resetting the classroom environment

Only do this if:

- your dataset is incorrect;
- you accidentally created or changed a lot of data; or
- the instructor asks you to reset the environment.

Run:

```bash
docker compose down -v
```

Then start again:

```bash
docker compose up --build -d
```

Prepare the database:

```bash
docker compose exec backend python manage.py migrate
```

Recreate the classroom dataset:

```bash
docker compose exec backend python manage.py seed_comprehension_data
```

Finally, generate a new development login:

```bash
docker compose exec backend python manage.py devlogin student@example.com --org MicroPyramid
```

> **Warning:** `docker compose down -v` deletes the local BottleCRM database. Do not use it if you want to keep work you have done inside BottleCRM.

# Troubleshooting

## Docker cannot connect to the Docker daemon

Make sure Docker Desktop is running. Then try:

```bash
docker info
```

again.

## `docker compose` is not available

Check:

```bash
docker compose version
```

If this fails, make sure you installed a current version of Docker Desktop.

## A port is already allocated

You may see an error similar to:

```text
Bind for 0.0.0.0:6379 failed: port is already allocated
```

This usually means another Docker container is already using the port.

Run:

```bash
docker ps
```

Check whether another copy of BottleCRM or another container is already running. If it is an older BottleCRM environment that you no longer need, stop it before starting this repository.

If you are unsure which container to stop, ask the instructor rather than stopping unrelated containers.

## The browser says "site can't be reached"

First check:

```bash
docker compose ps
```

Make sure the frontend container is running.

Then check:

```bash
docker compose logs frontend --tail=50
```

You should see Vite reporting that the frontend is running.

Open:

```text
http://localhost:5181
```

in your browser.

## The frontend cannot connect to `127.0.0.1:8000`

You may see an error such as:

```text
connect ECONNREFUSED 127.0.0.1:8000
```

Inside Docker, `localhost` refers to the container itself. The frontend and backend are separate containers.

The classroom repository should already be configured correctly for this. Do not start changing application code to fix this. Record the error and check with the instructor.

## `column ... does not exist`

If you see a database error such as:

```text
column users.name does not exist
```

or:

```text
column organization.timezone does not exist
```

first run:

```bash
docker compose exec backend python manage.py migrate
```

Then retry the command that failed.

If the problem remains, use the full reset procedure described above.

## Seeding reports duplicate data

Do not repeatedly run the seed command.

If the classroom data has become inconsistent, use the reset procedure:

```bash
docker compose down -v
```

and then follow the setup steps again.

## Login still asks for an email link

Do not request another email.

Run:

```bash
docker compose exec backend python manage.py devlogin student@example.com --org MicroPyramid
```

and use the JavaScript printed by that command in the browser console.

## Before the classroom exercise

Make sure all of the following are true:

- Docker Desktop starts correctly.
- `docker compose ps` shows the BottleCRM services running.
- `http://localhost:5181` opens BottleCRM.
- You can log in as `student@example.com`.
- The Leads page shows the five classroom leads.

Once these checks pass, **do not explore the source code in advance**. You will investigate the system during the classroom exercise.

---

## Important classroom rules

During setup:

- Do not modify the BottleCRM application code.
- Do not change database records manually.
- Do not run other seed commands.
- Do not add large amounts of test data.
- Do not try to "fix" behaviour that appears unusual.
- Do not explore the implementation before the exercise begins.

If the application behaves differently from the setup described above, record what happened and ask the instructor.

The objective of this setup is simply to make sure everyone starts with the same running system.

---

## Classroom-specific additions

This repository is based on BottleCRM.

A small number of additions and configuration changes have been made to make it suitable for the classroom environment. These include:

- a small deterministic classroom dataset;
- the `seed_comprehension_data` command;
- the `devlogin` command for local development login;
- Docker configuration required for the classroom environment.

These utilities exist to make setup easier. They are not part of the behaviour you are expected to study unless specifically instructed.

For information about the original BottleCRM project, see the main README and the original project documentation.
